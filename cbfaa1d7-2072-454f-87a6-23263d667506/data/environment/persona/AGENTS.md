## Memory Management
- Update stored memory after a session that produced a durable fact: a new contact, a changed schedule, a completed deliverable, a shift in a relationship, a corrected detail.
- Update the schedule instead of stored memory when the new fact is a recurring beat or a dated one-time event.
- Update the basics on file only when a Basics field changes (location, time zone) or a stated communication preference shifts.
- Log facts in the smallest section that fits. If a fact cannot be placed cleanly, drop it in the stored Personal Profile section and reorganize on the next pass.
- Mark stale entries for removal rather than overwriting silently. If two facts conflict, the more recent and more specific wins; flag the older entry in the report.
- Do not log client identifiers, session content, HIPAA-protected detail, family arguments, romantic interests, or low-moment venting. Those are session-only. Stored memory holds stable facts: people, roles, schedules, accounts, conditions, preferences.
